## 1. Introduction to Virtual Memory
Virtual Memory is a memory management technique implemented through hardware (MMU) and software (OS). It abstracts physical memory into a **Virtual Address Space**.

* **Goal:** Map virtual addresses generated by programs into physical addresses in computer memory.
* **Core Aspects:**
    * **Address Translation:** Converting virtual addresses to physical ones.
    * **Management:** The OS assigns real memory to virtual spaces.
* **Primary Benefits:**
    * Frees programmers from managing shared memory space.
    * Enhances security via memory isolation between processes.
    * Enables the system to use more memory than is physically available.

## 2. Key Components
* **Pages:** Contiguous blocks of virtual memory addresses (usually 4 KB).
* **Page Table:** A data structure managed by the OS that stores mappings between virtual and physical addresses.
* **MMU (Memory Management Unit):** Hardware on the CPU chip that handles the actual translation.
* **TLB (Translation Lookaside Buffer):** A high-speed cache within the MMU that stores recently used mappings to speed up translation.

## 3. Address Translation Process
The MMU follows a specific hierarchy to find a physical address:
* **Step 1:** The MMU checks the **TLB Cache**.
* **Step 2 (TLB Hit):** If found, the physical address is returned immediately.
* **Step 3 (TLB Miss):** The MMU performs a **Page Walk** by searching the full Page Table.
* **Step 4:** If the mapping is found in the Page Table, it is written to the TLB for future use, and the translation restarts.

## 4. Handling Page Faults
A translation can fail for two primary reasons:
* **Segmentation Fault:** The process attempts to access an invalid or unauthorized memory area.
* **Page Fault:** The requested page is valid but currently stored on secondary storage (disk) instead of RAM.
    * The OS **Page Supervisor** takes control.
    * It retrieves the page from the disk and loads it into a physical memory frame.
    * The Page Table and TLB are updated, and the instruction is retried.

## 5. Paging and Swapping
When physical memory is full, the OS must make room for new pages.
* **Swapping:** The process of moving pages between main memory (RAM) and secondary storage (Disk).
* **Page Replacement Algorithms:** Used to decide which page to "evict" to disk. Common methods include:
    * **LRU (Least Recently Used):** Swaps out the page that hasn't been accessed for the longest time.

## 6. Kernel vs. User Virtual Memory
In a typical 32-bit Linux OS, the 4GB address space is split:
* **User Space (3 GB):** Dedicated to user applications.
* **Kernel Space (1 GB):** Reserved for the OS kernel.
    * **Isolation:** The kernel space is constant and maps to the same physical memory across all process context switches.
    * **Persistence:** On Linux, kernel code and data are usually kept in main memory (never swapped) to ensure the Page Fault handler is always available to run.
